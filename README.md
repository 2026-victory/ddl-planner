# DDL 不慌 · 智能任务规划

一个能在手机上用的「DDL 小程序」：把任务按**紧急度 × 重要度 × 难度 × 工作量**自动排序，把大任务拆成小步骤，再把它们切成 25~45 分钟的时间块排进你的一日行程，并提前提醒你。

支持**重复任务**（每周一自动排满每个周一）、**指定时间段**（锁定在你要的时间）、**账号登录与云端同步**（换设备能取回）。

> 🚀 想放到网上用 → 看 **[GET-ONLINE.md](GET-ONLINE.md)**（手把手拿到网址）
> 📱 想装成手机 App → 看 **[MAKE-APP.md](MAKE-APP.md)**（生成安卓 APK，无需开发环境）
> 🔄 以后怎么更新 → 看 **[UPDATE.md](UPDATE.md)**（改代码后如何发版）
> 🔧 要看完整部署细节与运维 → **[DEPLOY.md](DEPLOY.md)**

## 一、怎么用（三种方式）

### 方式 1：只自己用，单文件 HTML

1. 找到 `dist/DDL不慌.html`（就一个文件）
2. 传到手机 → 用浏览器打开

⚠️ **不要用「添加到桌面」**（第二天会打不开），改用**书签/收藏**保存入口。原因见「五·五」章节。

### 方式 2：本机起服务（有账号、能同步）

```bash
node build.js     # 构建前端
node server.js    # 启动，默认 http://localhost:3000
```

手机连同一 Wi-Fi，访问 `http://电脑IP:3000`。

### 方式 3：部署到公网（推荐，随时随地用）

把 `server.js` + `app/` 部署到 Render / Railway / VPS，得到固定 https 网址。

- 手把手跟着做 → **[GET-ONLINE.md](GET-ONLINE.md)**
- 完整细节与运维 → **[DEPLOY.md](DEPLOY.md)**

> 注意：**纯静态托管（GitHub Pages / Vercel 静态）不能登录账号**，
> 因为那里无法运行后端。要账号必须部署带 `server.js` 的版本。

## 二、核心功能

### 1. 一句话添加任务

点底部中间的 **＋**，直接打一句话：

> `周五下午3点前交实验报告，大概要4小时，很难`

应用会自动识别并回填：

| 识别项 | 例子 |
|---|---|
| 日期 | 今天 / 明天 / 后天 / 周五 / 下周三 / 3天后 / 12月20日 / 月底 |
| 时间 | 下午3点、今晚8点、15:30、晚上8点前 |
| 时长 | 2小时、90分钟、半小时 |
| 难度 | 很难 / 烧脑 → 4~5，简单 → 2 |
| 重要度 | 最重要 / 必须 → 5，不急 → 2 |

识别结果会立刻显示在表单里，**可以手动改**。

### 2. 优先级排序（这是它真正在帮你做的判断）
`优先级分数 = 紧急度 40% + 重要度 30% + 难度 15% + 工作量 15%`

- **紧急度**：按「剩余工时 ÷ 剩余天数」计算，不是只看日期。10 小时的活还剩 2 天，比 30 分钟的活还剩 1 天更急。
- **兜底压力**：明天截止至少 0.86，3 天内至少 0.64，7 天内至少 0.45；临期再额外加分。
- **难度**：难的任务早点开始，避免最后一天硬扛。
- 每个任务的详情页都会告诉你**为什么排在这个位置**（"今天截止 · 重要度高 · 难度大，宜早开始"）。

### 3. 大任务智能拆解

详情页点「智能拆解」，按任务类型套用不同的专家模板：

| 类型 | 识别关键词 | 步骤数 |
|---|---|---|
| 论文/研究 | 论文、毕设、文献、综述 | 9 步 |
| 编程/项目 | 开发、小程序、系统、部署 | 8 步 |
| 作业/习题 | 作业、习题、实验报告 | 6 步 |
| 考试/备考 | 考研、复习、四六级 | 7 步 |
| 汇报/PPT | 汇报、PPT、答辩、方案 | 7 步 |
| 演讲/答辩 | 演讲、路演、宣讲 | 7 步 |
| 求职/面试 | 简历、面试、秋招 | 7 步 |
| 设计/创作 | 海报、UI、作品集 | 7 步 |
| 写作/内容 | 文章、公众号、剧本 | 7 步 |
| 学习/课程 | 课程、网课、读完 | 6 步 |
| 通用兜底 | 其他 | 7 步 |

每个步骤都带：**名称 + 工时（按权重自动分配总工时）+ 阶段（启动/推进/收尾）+ 建议完成日期（按截止日倒推）**。
可以改标题、改工时、删步骤、加步骤，或者「重新生成」。

> 工时太小的任务（比如只有 20 分钟的「交个表」）不会硬凑 7 步，会自动压缩到 3 步。

### 4. 自动排程（今日时间线）

点开「今天」，会看到一条时间线：

- 从你设置的**开始时间**（默认 08:30）排到**结束时间**（默认 22:30）
- 自动**绕开固定安排**（上课、开会、通勤）
- 每个时间块最长 **45 分钟**，块间留 **10 分钟休息**
- 按优先级从高到低填充，颜色条表示优先级档位
- 每个任务每天只排「今天该做的量」：`剩余工时 ÷ (剩余天数 + 1)`，避免一个大任务把一周全占满
- 排不下会明确告诉你「今天排不下 XX 小时」，而不是假装能做完

### 5. 日历

- 月视图，每天用彩色圆点标记：红=重要任务、黄=一般任务、蓝=固定安排、绿=已排工作量
- 点任意一天，下面立刻显示：当天任务 + 固定安排 + 当天建议行程
- 可以给某天加固定安排（上课、通勤、会议）

### 6. 专注计时 + 提醒

- 点时间块右侧的 ▶ 进入专注模式：45 分钟倒计时环，可暂停、可提前结束，结束后**自动累加到该任务已用时长**
- 任务到期前 N 分钟（默认 10 分钟）弹出提醒 + 震动
- 只有日期的任务，当天早上提醒一次
- 21:00 后预告明天的任务

> 浏览器通知需要 HTTPS 或 localhost，并且要手动授权。单文件版（file://）只能应用内提醒 + 震动。

### 7. 重复任务（每周一自动排满）

新建任务时选择「重复」：

| 选项 | 效果 |
|---|---|
| 每天 | 连续每天的同一时间 |
| 工作日 | 周一到周五 |
| **每周** | 选星期几（如每周一），自动排满之后所有周一 |
| 每月 | 选几号（如每月15日） |

- 可以设「重复到哪天为止」，留空则一直重复（最多排到 90 天后）
- 重复任务会在**日历、今天页、未来排程**里都出现
- 一次添加，会生成一个系列（共享 `seriesId`），便于整体管理

例：输入「每周一交周报」+ 选「每周·一」→ 系统立刻把未来 90 天里所有周一都排上。

### 8. 指定时间段（锁定在你要的时间）

新建任务时填「指定时间段」（如 14:00–15:30）：

- 工时**自动等于**时段长度（90 分钟）
- 排程时**锁定**在这个窗口，不会被优先级排序挪走
- 也**不会被 45 分钟上限切碎**（一口气排完）
- 与「固定安排」不冲突：先占固定安排，再把锁定块放进去
- 如果今天的这个时段已经过去，就跳过今天，**不会擅自挪到别的时间**

不填时间段的任务，仍然由系统按优先级自动分配。

### 9. 账号与云端同步

点右上角头像或设置里的「账号与同步」：

- **注册只需账号名**，密码可选（留空即免密登录）
- 登录后数据自动同步到云端，**换手机登录同一账号就能拿回全部安排**
- 未登录时和以前一样纯本地，不影响离线使用
- 退出登录后本机数据保留

> 账号功能需要后端（`node server.js` 或部署到网上）。详见 [DEPLOY.md](DEPLOY.md)。

### 10. 数据与导出

- **导出到日历**：生成 `.ics`，导进手机自带日历（含截止日期与 14 天行程）
- **备份 / 恢复**：导出/导入 JSON，换设备不丢数据
- **找回上次数据**：从自动备份恢复
- **清空**：回到空白状态

## 五·五、⚠️ 不要用「添加到桌面」打开本地 HTML（重要）

这是你遇到「第二天打不开、数据初始化」的直接原因，务必看完。

### 为什么会这样

| 现象 | 原因 |
|---|---|
| 第二天图标点不开 | 手机浏览器**不允许桌面快捷方式冷启动 `file://` 本地文件**，这是浏览器的安全限制，不是文件坏了 |
| 重新添加后数据没了 | `localStorage` **按入口隔离**。重新添加 = 新的存储空间 = 读不到旧数据 |

我用真实浏览器验证过：同一台设备上，`file://` 和 `http://` 的存储**完全隔离**（互不可见），
所以「换个方式打开」在浏览器看来就是「换了一个新应用」。

### 现在怎么用才稳

**推荐：用书签，不要用桌面图标**

在浏览器打开后，把它加入**收藏夹/书签**。以后从书签进入，存储空间永远不变。

**最推荐：部署到能跑后端的平台（真 PWA + 账号）**

把 `server.js` 和 `app/` **一起**部署到 Render / Railway 这类能运行 Node 的平台，
拿到 https 网址后再「添加到主屏幕」——这时的图标是真正的 PWA，数据稳定、可离线、重启也在，
而且**账号同步可用**。

⚠️ 注意区分：**纯静态托管（GitHub Pages / Vercel 静态 / Netlify）放不了后端**，
只能让应用跑起来、不能登录账号。详见 [DEPLOY.md](DEPLOY.md)。

### 已经帮你兜住了：自动备份 + 找回

现在即使换了入口，数据也能捞回来：

- 每次保存都会同步写一份**自动备份**（`ddl-planner-autobackup`）
- 换入口打开时，如果主存储为空但备份存在 → **自动恢复**，并弹窗告知
- 设置页新增「**找回上次数据**」按钮，可随时手动恢复
- 设置页新增「**当前存储位置**」说明，一眼看出你在哪种模式

> 注意：自动备份和主数据在**同一个浏览器**里。如果清了浏览器缓存，两者都会没，所以**重要数据请定期「备份数据」导出 JSON**。

### 如果你已经丢了数据

先别急着重录：

1. 用**同一个浏览器**（之前用的那个）重新打开原来的文件/书签
2. 如果看到「已找回你上次的数据」弹窗 → 数据已回来
3. 如果没有，去设置页点「找回上次数据」
4. 还是没有 → 说明当时换了浏览器或清了缓存，只能从之前的 JSON 备份恢复

## 五·六、保存相关的修复记录

- **勾选完成不落盘**：`toggle-task` 修改了任务状态但漏调 `save()`，导致勾选完成后关掉页面状态丢失。已修复。
- **清空后示例数据复活**：旧逻辑会在用户清空后重新注入示例任务。改为仅新用户注入。
- **存储失败不可见**：原先只是 console.warn。现在渲染顶部红色警告条并给出备份入口。
- **换入口数据"初始化"**：新增自动备份 + 自动恢复 + 手动找回，并把「本地文件模式」的风险直接写在设置页。

### 数据分层

| 键 | 用途 |
|---|---|
| `ddl-planner-v1` | 主数据（当前入口） |
| `ddl-planner-autobackup` | 自动备份（每次保存同步更新，用于跨入口找回） |
| `ddl-planner-origin` | 记录上次使用的入口，便于诊断 |

## 六、已知边界

- 数据存在**当前浏览器**，换浏览器 / 清缓存会丢，请定期备份
- `file://` 单文件版无法注册 Service Worker，因此没有系统级推送通知（应用内提醒正常）
- 拆解模板是规则化的领域知识，不调用大模型；步骤可编辑，建议按自己习惯微调
- 自动排程是贪心算法，优先级高的先占时间；如果需要"番茄钟式轮换"，改 `core.js` 的 `planDay` 即可
